ORDEN DE EJECUCIÓN — F04

Secuencia cronológica de archivos que intervienen desde que se gatilla un evento hasta que la barrera se abre. Cada flujo está numerado en orden de ejecución real.

CAPAS DEL SISTEMA

Cada archivo pertenece a una capa, identificada por una etiqueta de color en los listados:

Frontend Interfaz de Operador

JavaScript en el navegador. Captura clics, muestra formularios y dispara peticiones HTTP a la API.

API Rutas (endpoints)

FastAPI routers. Punto de entrada del backend. Valida parámetros, aplica guards de seguridad y delega en servicios.

Servicios Lógica de negocio

Clases de servicio. Validan reglas de negocio (acceso, pago, aforo) y orquestan operaciones de base de datos y MQTT.

Core Infraestructura

Configuración, base de datos, seguridad, MQTT, WebSockets. Proveen servicios transversales a todas las capas.

IoT Hardware

Firmware ESP32. Recibe el comando MQTT y acciona físicamente el servomotor de la barrera.

FLUJOS DE EJECUCIÓN

Automático Entrada por ALPR

El ALPR detecta una patente y envía la solicitud al backend. La validación, publicación MQTT y apertura física ocurren en cadena.

  1. Servicios services/alpr_service.py → Detecta el vehículo por cámara, aplica OCR con EasyOCR y envía POST /v1/access/validate-plate con la patente detectada.
  2. API routes/parking/access.py → Recibe la solicitud en validate_plate(). Aplica el schema PlateValidation y delega en AccessService.
  3. API routes/parking/utils.py → normalize_plate() limpia la patente (mayúsculas, sin espacios ni guiones).
  4. Servicios services/access_service.py → validate_plate() verifica: reservas activas, aforo disponible, tipo de vehículo. Si ok, publica MQTT y registra el ingreso.
  5. Core core/database.py → get_db() inyecta la sesión de SQLAlchemy para todas las consultas a base de datos.
  6. Core core/config.py → Settings provee MQTT_TOPIC_ENTRADA, DATABASE_URL, entre otras variables de entorno.
  7. Servicios services/notification_service.py → notify_occupancy_change() dispara la actualización de aforo por WebSocket (en paralelo al paso 8).
  8. Core core/mqtt.py → get_mqtt_client() publica {"command": "OPEN"} en el tópico parking/barrera/entrada/control.
  9. IoT firmware_esp32.ino → El ESP32 de entrada recibe el mensaje MQTT, muestra la patente en LCD, acciona el servomotor a 90° y cierra al detectar paso (sensor ultrasónico >20 cm).
  10. Core models/parking.py → Se crea un AccessLog con tipo_evento=ENTRADA y se actualiza ParkingAforo.ocupacion_actual.
  11. API routes/parking/status.py → OccupancyManager.broadcast_update() envía el nuevo aforo a todos los dashboards conectados vía WebSocket.

Manual Entrada Manual

El operador abre la barrera y registra el vehículo cuando el ALPR no puede leer la patente.

  1. Frontend static/js/dashboard.js → El operador hace clic en "Abrir Barrera". Se ejecuta openBarrier('ENTRADA') (expuesta desde dashboard-admin.js).
  2. Frontend static/js/modules/dashboard-admin.js → openBarrier() muestra confirmación, cambia el ícono de la barrera y llama a api.post('/admin/open-barrier?gate_id=ENTRADA').
  3. Frontend static/js/modules/utils.js → showConfirm() muestra el modal de confirmación. showToast() notifica el resultado.
  4. API routes/admin/operations.py → open_barrier(gate_id='ENTRADA') publica {"command":"OPEN"} por MQTT en el tópico de entrada.
  5. Core core/security.py → get_operational_user() valida el JWT y verifica que el usuario tenga rol staff/admin/local_admin.
  6. Core core/mqtt.py → Publica {"command":"OPEN"} en parking/barrera/entrada/control.
  7. IoT firmware_esp32.ino → El ESP32 recibe el comando y abre la barrera físicamente.
  8. Frontend static/js/dashboard.js → El operador completa el formulario "Entrada manual". Se ejecuta manualEntry().
  9. Frontend static/js/modules/utils.js → formatPlate() da formato a la patente. showConfirm() pide confirmación antes de enviar.
  10. API routes/admin/operations.py → manual_entry() recibe plate, tipo_vehiculo y floor_id. Valida duplicados y registra el ingreso.
  11. API routes/parking/utils.py → normalize_plate() normaliza la patente ingresada.
  12. Core core/database.py → Sesión de base de datos para consultar y persistir.
  13. Core models/parking.py → Crea AccessLog con tipo_evento=ENTRADA. Actualiza ParkingFloor o ParkingAforo.
  14. Servicios services/notification_service.py → OccupancyManager.broadcast_update() refleja el cambio en dashboards en tiempo real.

Automático Salida por ALPR

El ALPR de salida detecta la patente. El sistema verifica el pago y abre la barrera.

  1. Servicios services/alpr_service.py → Detecta el vehículo en la salida y envía POST /v1/access/exit-plate.
  2. API routes/parking/access.py → exit_plate() recibe la solicitud y delega en AccessService.exit_plate().
  3. Servicios services/access_service.py → exit_plate() verifica que el vehículo esté dentro y tenga pago_confirmado=True.
  4. Servicios services/billing_service.py → Consulta el estado del pago y calcula deuda si corresponde (vía process_payment() en paso previo).
  5. Core core/mqtt.py → Publica {"command":"OPEN"} en parking/barrera/salida/control.
  6. IoT firmware_esp32.ino → El ESP32 de salida abre la barrera. El sensor ultrasónico detecta el paso y cierra.
  7. Core models/parking.py → Crea AccessLog con tipo_evento=SALIDA. Decrementa ParkingAforo.
  8. API routes/parking/status.py → OccupancyManager.broadcast_update() actualiza dashboards vía WebSocket.

Manual Salida Manual

El operador abre la barrera de salida y registra la salida del vehículo. Dos acciones independientes en el dashboard.

  1. Frontend static/js/dashboard.js → El operador hace clic en "Abrir Barrera" de salida. openBarrier('SALIDA').
  2. Frontend static/js/modules/dashboard-admin.js → openBarrier('SALIDA') llama a api.post('/admin/open-barrier?gate_id=SALIDA').
  3. API routes/admin/operations.py → open_barrier(gate_id='SALIDA') publica MQTT en el tópico de salida.
  4. Core core/mqtt.py → Publica {"command":"OPEN"} en parking/barrera/salida/control.
  5. IoT firmware_esp32.ino → El ESP32 de salida recibe el comando y abre la barrera.
  6. Frontend static/js/dashboard.js → El operador hace clic en "Salida manual". manualExit(plate, type).
  7. API routes/admin/operations.py → manual_exit() verifica que el vehículo exista y tenga pago_confirmado=True. Registra la salida.
  8. API routes/parking/utils.py → normalize_plate() normaliza la patente.
  9. Core models/parking.py → Crea AccessLog con tipo_evento=SALIDA. Decrementa aforo.
  10. API routes/parking/status.py → OccupancyManager.broadcast_update() actualiza dashboards.

QR Salida por QR / Pase Digital

El ALPR detecta un código QR en lugar de una patente, o el usuario presenta un pase digital desde su móvil.

  1. Servicios services/alpr_service.py → Detecta el QR en la cámara de salida y envía POST /v1/access/validate-qr con el contenido del QR.
  2. API routes/parking/access.py → validate_qr() recibe la solicitud y delega en AccessService.validate_qr().
  3. Servicios services/access_service.py → validate_qr() interpreta el QR (reserva o pase), valida vigencia y autoriza la salida.
  4. Core core/mqtt.py → Publica {"command":"OPEN"} en parking/barrera/salida/control.
  5. IoT firmware_esp32.ino → El ESP32 de salida abre la barrera.
  6. API routes/parking/status.py → OccupancyManager.broadcast_update() actualiza dashboards.

DEPENDENCIAS TRANSVERSALES

Archivos que intervienen en todos los flujos, sin importar la vía de entrada:

  • core/config.py → Clase Settings. Lee variables de entorno. Dependencia de core/mqtt.py, core/database.py, core/security.py, services/access_service.py, services/billing_service.py y routes/admin/operations.py.
  • core/database.py → get_db() — Inyecta sesión SQLAlchemy en todos los endpoints y servicios. Usa core/config.py para la URL de conexión.
  • core/security.py → get_operational_user(), get_current_user() — Guards de autenticación JWT. Usado por routes/admin/operations.py y routes/parking/status.py.
  • models/__init__.py + models/parking.py → Clases ORM: AccessLog, ParkingAforo, ParkingFloor, Vehicle, Reservation. Usadas por todos los servicios y rutas.
  • models/enums.py → Enumeraciones compartidas: VehicleType, AccessEventType, UserRole. Usadas por services/access_service.py, services/billing_service.py, core/security.py.
  • schemas/__init__.py → Schemas Pydantic: PlateValidation, QRValidation, AccessResponse. Usados por routes/parking/access.py y services/access_service.py.
  • static/js/modules/api.js → Módulo HTTP con api.get(), api.post(), etc. Usado por todos los módulos JS del frontend.
