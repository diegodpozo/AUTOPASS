# EXPLICACION DEL CODIGO - SISTEMA AUTOPASS

ESTE DOCUMENTO DETALLA EL FUNCIONAMIENTO DEL SISTEMA DE GESTION DE ESTACIONAMIENTO INTELIGENTE (V9.2.0).

## 1. ARQUITECTURA GENERAL
EL SISTEMA SE COMPONE DE CUATRO CAPAS PRINCIPALES:
* **BACKEND (API):** FASTAPI CON ARQUITECTURA LIMPIA (CAPAS: ROUTES, SERVICES, MODELS, SCHEMAS).
* **SERVICIO ALPR:** CAPTURA DE VIDEO Y RECONOCIMIENTO DE TEXTO EN PATENTES (OPENCV + EASYOCR).
* **WORKER SERVICE:** PROCESOS DE FONDO (LIMPIEZA DE RESERVAS VENCIDAS, LIBERACION AUTOMATICA DE AFORO).
* **HARDWARE (ESP32):** CONTROLA LOS ELEMENTOS FISICOS (BARRERAS, SENSORES, PANTALLAS VIA MQTT).

---

## 2. COMPONENTES TECNICOS

### BACKEND (CORE, ROUTES, SERVICES, MODELS)
* **TECNOLOGIA:** FASTAPI, SQLALCHEMY, PYDANTIC.
* **LOGICA DE ACCESO (`services/access_service.py`):** CUANDO RECIBE UNA PATENTE DESDE EL SERVICIO ALPR:
  1. VERIFICA SI EL VEHICULO YA ESTA DENTRO (EVITA DUPLICADOS).
  2. BUSCA UNA RESERVA PAGADA VIGENTE.
  3. SI HAY RESERVA NO HORARIA (DIA/SEMANA/QUINCENA/MES): PERMITE EL INGRESO SIN INCREMENTAR EL AFORO (YA SE RESERVO EN EL PAGO).
  4. SI HAY RESERVA POR HORA: PERMITE EL INGRESO E INCREMENTA EL AFORO.
  5. SI NO HAY RESERVA: VERIFICA CAPACIDAD (MODO "AL PASO").
* **PAGO EN SALIDA (`pay_stay`):** PERMITE AL CLIENTE PAGAR LA ESTADIA ANTES DE SALIR. CALCULA COSTO CON `BILLING_SERVICE` Y REGISTRA `METODO_PAGO`, `FECHA_PAGO`.
* **SALIDA CON VERIFICACION (`exit_plate`):** VALIDA QUE EL VEHICULO HAYA PAGADO (O TENGA RESERVA VIGENTE) ANTES DE ABRIR BARRERA. SI NO, RECHAZA LA SALIDA.
* **CANCELACION DE ESTADIA (`cancel_stay`):** CANCELA UNA ESTADIA ACTIVA Y OTORGA 10 MINUTOS DE CORTESIA (NO COBRA).
* **VALIDACION QR:** ENDPOINT `validate_qr` QUE DECODIFICA QR Y VERIFICA RESERVA O PERMISO DE ACCESO.
* **LOGICA DE SALIDA:** AL DETECTAR UNA SALIDA:
  - SI EL VEHICULO TIENE RESERVA NO HORARIA PAGADA: NO LIBERA LA PLAZA (LA GESTIONA AUTO_FINALIZE AL VENCER).
  - SI NO: LIBERA LA PLAZA DEL AFORO NORMALMENTE.
* **GESTION DE RESERVAS (`services/reservation_service.py`):**
  - AL PAGAR UNA RESERVA NO HORARIA: RESERVA LA PLAZA EN EL AFORO (`_reservar_plaza_en_aforo`).
  - AL CANCELAR: LIBERA LA PLAZA (`_liberar_plaza_en_aforo`).
  - AL VENCER (WORKER): LIBERA LA PLAZA AUTOMATICAMENTE.
* **COMUNICACION CON HARDWARE:** SI EL ACCESO ES VALIDO, ENVIA UN MENSAJE POR **MQTT** PARA QUE LA BARRERA SE ABRA.

### SERVICIO DE RECONOCIMIENTO (ALPR_SERVICE.PY)
* **TECNOLOGIA:** OPENCV (PARA PROCESAMIENTO DE IMAGENES) Y EASYOCR (PARA LECTURA DE TEXTO).
* **MODOS DE OPERACION:**
  - `SCREEN_TO_SCREEN`: SIMULACION CON VIDEO DE ARCHIVO (DESARROLLO).
  - `SCREEN_TO_CAMERA`: CAMARAS IP REALES (PRODUCCION).
* **FUNCIONAMIENTO:**
  1. CAPTURA EL VIDEO DE UNA CAMARA (O ARCHIVO).
  2. PROCESA LOS CUADROS (FRAMES) PARA MEJORAR EL CONTRASTE.
  3. BUSCA PATRONES QUE PAREZCAN PATENTES (FORMATOS MERCOSUR Y VIEJOS).
  4. SISTEMA DE CONSENSO: BUFFER DE VOTOS (MULTIPLES LECTURAS IGUALES ANTES DE ENVIAR).
  5. CUANDO LOGRA UN CONSENSO, ENVIA LA PATENTE AL BACKEND.
* **CARACTERISTICAS AVANZADAS:**
  - **DETECCION DE QR**: ESCANEO DIRECTO DE QR EN CADA FRAME (QUICK QR) COMO ALTERNATIVA A PATENTE.
  - **HEARTBEAT**: ENVIA PULSOS PERIODICOS A `/v1/system/heartbeat` PARA MONITOREO.
  - **VIDEO WEBSOCKET**: ENVIA FRAMES EN TIEMPO REAL A `/v1/system/ws/video/{gate_id}`.
  - **COLA DE FRAMES**: POLITICA DROP-OLDEST PARA EVITAR ACUMULACION.
  - **DETECCION DE MOVIMIENTO**: IGNORA FRAMES ESTATICOS.
  - **RECORTE MERCOSUR**: DETECTA Y RECORTA BANDA AZUL DE PATENTES MERCOSUR.
  - **DEBUG**: GUARDA IMAGENES DE PATENTES ACEPTADAS (SOLO ARGENTINA).
  - **COOLDOWN**: EVITA RE-ENVIAR LA MISMA PATENTE DENTRO DE UN PERIODO.

### FIRMWARE DE HARDWARE (FIRMWARE_ESP32.INO)
* **TECNOLOGIA:** C++ PARA ARDUINO/ESP32.
* **FUNCIONAMIENTO:**
  1. SE CONECTA A WIFI Y SE SUSCRIBE A UN TOPICO DE MQTT.
  2. AL RECIBIR EL COMANDO "OPEN", ACTIVA UN **SERVOMOTOR** PARA LEVANTAR LA BARRERA Y MUESTRA UN MENSAJE EN UNA **PANTALLA LCD**.
  3. UTILIZA UN **SENSOR ULTRASONICO** PARA DETECTAR CUANDO EL AUTO TERMINO DE PASAR Y ASI CERRAR LA BARRERA DE FORMA SEGURA.

### WORKER SERVICE (SERVICES/WORKER_SERVICE.PY + NOTIFICATION_SERVICE.PY)
* **TECNOLOGIA:** THREADING + WEB SOCKETS.
* **FUNCIONAMIENTO:**
  1. EJECUTA `auto_finalize_all_reservations` CADA `MAINTENANCE_INTERVAL_SECONDS` (300s) PARA VENCER RESERVAS Y LIBERAR AFORO.
  2. NOTIFICA CAMBIOS DE AFORO A LOS DASHBOARDS EN TIEMPO REAL VIA WEBSOCKETS (NOTIFICATIONSERVICE CON `ASYNCIO.QUEUE` POR SUCURSAL).

### ADMIN OPERATIONS (ROUTES/ADMIN/OPERATIONS.PY)
* **OPERACIONES MANUALES PARA PERSONAL:**
  - `open_barrier`: ABRE BARRERA MANUALMENTE VIA MQTT.
  - `manual_entry`: REGISTRA ENTRADA MANUAL DE VEHICULO (PATENTE TIPEADA).
  - `manual_exit`: REGISTRA SALIDA MANUAL.
  - `cancel_stay`: CANCELA ESTADIA ACTIVA CON 10 MIN DE CORTESIA.

### SISTEMA DE FIDELIZACION (ROUTES/USER/FIDELIZATION.PY + POINTS_LOG)
* **PROMOCIONES:** CATALOGO DE BENEFICIOS (`PROMOTION`) CON ICONO, CATEGORIA, SUCURSAL, ACTIVA.
* **CANJE DE PUNTOS:** `redeem/{promo_id}` CANJEA PUNTOS POR UNA PROMOCION Y GENERA UN `COUPON`.
* **HISTORIAL:** `points-history` CON PAGINACION DE PUNTOS GANADOS Y CANJEADOS.
* **METAS:** BARRA DE PROGRESO CON METAS EN 500, 1000, 2500, 5000, 10000 PUNTOS.

### EMAIL SERVICE (SERVICES/EMAIL_SERVICE.PY)
* **TECNOLOGIA:** SMTPLIB + JINJA2.
* **FUNCIONES:**
  - `send_reservation_confirmation`: EMAIL CON QR EMBEBIDO, DATOS DE RESERVA, LOGO DE SUCURSAL.
  - `send_password_reset`: EMAIL DE RECUPERACION DE CONTRASEÑA CON TOKEN.
* **TEMPLATES:** `templates/emails/` CON HERENCIA DE `base_email.html`.

## 3. FLUJO DE USUARIO TIPICO (SIN RESERVA)
1. EL AUTO SE ACERCA A LA ENTRADA.
2. LA CAMARA DETECTA LA PATENTE O UN CODIGO QR.
3. `ACCESS_SERVICE` VERIFICA CAPACIDAD EN `PARKING_AFORO`.
4. SI HAY LUGAR: INCREMENTA OCUPACION, REGISTRA ACCESO, ABRE BARRERA VIA MQTT.
5. EL AUTO ESTACIONA, EL AFORO SE ACTUALIZA EN EL DASHBOARD VIA WEBSOCKET.
6. PARA SALIR: EL SISTEMA VERIFICA PAGO, LIBERA PLAZA, ABRE BARRERA.

## 4. FLUJO DE USUARIO CON RESERVA NO HORARIA (DIA/SEMANA/QUINCENA/MES)
1. EL CLIENTE RESERVA Y PAGA → SE DESCUENTA 1 PLAZA DEL AFORO.
2. EL CLIENTE PUEDE ENTRAR Y SALIR LIBREMENTE DURANTE EL PERIODO DE RESERVA.
3. LA PLAZA SIGUE OCUPADA EN EL DASHBOARD (RESERVADA PARA EL CLIENTE).
4. AL VENCER EL PERIODO, EL WORKER LIBERA LA PLAZA AUTOMATICAMENTE.

## 5. BASE DE DATOS
SE UTILIZA **SQLITE** (O POSTGRESQL EN PRODUCCION) CON LAS SIGUIENTES TABLAS:
* **USERS / VEHICLES:** DATOS DE CLIENTES Y SUS AUTOS/MOTOS/CAMIONETAS. `USERS` INCLUYE `APELLIDO`, `DNI`, `TELEFONO`, `DIRECCION`, `SALDO`, `IS_BLOCKED`. `VEHICLES` INCLUYE `TIPO` (AUTO/MOTO/CAMIONETA).
* **RESERVATIONS:** CALENDARIO DE ACCESOS PROGRAMADOS (SOPORTA HORA, DIA, SEMANA, QUINCENA, MES). INCLUYE `MONTO_REEMBOLSADO`, `SUCURSAL_INFO` (JSON), `CLIENTE_NOMBRE`.
* **ACCESS_LOGS:** HISTORIAL DETALLADO DE ENTRADAS, SALIDAS Y FOTOS CAPTURADAS. INCLUYE `NORMALIZED_PATENTE`, `FLOOR_ID`, `COSTO_ESTADIA`, `METODO_PAGO`, `FECHA_PAGO`, `STATUS`, `TIPO_VEHICULO`.
* **PARKING_AFORO / PARKING_FLOORS:** ESTADO ACTUAL DE LA OCUPACION (SOPORTE MULTI-PISO). `PARKING_FLOORS` INCLUYE `CAPACIDAD_MOTOS`, `OCUPACION_MOTOS`.
* **PARKING_BRANCHES:** CONFIGURACION DE SUCURSALES (TARIFAS, HORARIOS, DIRECCION). INCLUYE `LOGO_URL`, `ACTA`, `LATITUDE`, `LONGITUDE`, `FLOORS` (RELACION).
* **PROMOTIONS / POINTS_LOG:** SISTEMA DE FIDELIZACION Y PUNTOS. `PROMOTIONS` INCLUYE `ICONO`, `CATEGORIA`, `SUCURSAL`, `ACTIVA`.
* **COUPONS:** CUPONES GENERADOS POR CANJE DE PUNTOS.
* **SETTINGS:** KEY-VALUE STORE CON `VALOR_STR` PARA TEXTOS (IPS DE CAMARAS) Y `SUCURSAL` PARA AISLAMIENTO.
